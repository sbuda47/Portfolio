How the original project connects sensing, monitoring, and control.

01 / OBSERVE

Camera, LiDAR & motor data

Belt inspection identifies visible wear. LiDAR estimates the stockpile. The health index describes motor condition.

02 / BRING TOGETHER

NVIDIA Jetson Nano

The Python application brings subsystem results together and supplies the Streamlit dashboard. I was the main operator of this integrated setup.

03 / RESPOND

ESP32 controller

The controller handles scanning and belt-speed control, using system health and stockpile level to inform its response.

The original system supports hardware, replay, and simulated inputs. Camera inference can run on a separate computer, with its results returned to the Jetson.

A system built to work together.

Our final-year project combined belt inspection, stockpile measurement, and motor-health monitoring in one supervisory system. The dashboard made the results visible, while an ESP32 controller handled scanning and belt-speed control. The aim was to help an operator see both equipment condition and material flow without jumping between disconnected tools, allowing them to make informed and smarter decisions.

My contribution

I developed the motor health index, turning changes in sensor behaviour into a score that is easier to interpret.

I was also the main person operating the complete system on the Jetson Nano, and assisted across the other subsystems as we brought the project together.

A little more about the engineering

How the health index helps

The Mahalanobis-distance health index looks at how sensor readings change together, rather than judging every reading in isolation. It translates that change into a health score, making deterioration easier to recognise.

What this preview represents

The original interface was built in Streamlit. This portfolio version reorganises its key views for the browser. Motor charts use selected rows from the repository’s replay files; stockpile scans are synthetic references; the belt snapshot uses illustrative values. It does not run inference or control equipment.
