Telemetry & communications — 5-person team project

Environmental Telemetry Monitoring System

How well can air-quality readings survive transmission and still support useful monitoring? Our five-person team built an end-to-end Python simulation using real urban sensor data. We prepared the signals, compared five ways of transmitting them through noise, recovered the information, and built digital encoding and monitoring stages.

I led signal preprocessing: checking sensor quality, handling missing readings, and preparing filtered signals for the transmission tests. The replay below demonstrates this part of the wider system.

About this replay and its data

An accelerated replay of 168 hourly samples from the project’s TURDATA exports, covering 16–23 August 2022. This is recorded data, not live air-quality monitoring. “Before filtering” is the already-preprocessed value_raw column; “Filtered” is the exported value_sg column. Neither is a calibrated reference measurement.

The original filter uses an 11-sample window and a quadratic fit. The preview displays saved outputs without recalculating them. The chart scale adjusts for each pollutant; gas concentrations use ppb and particulate concentrations use µg/m³.

Selected source: data/processed/selected_segments/NO2_S10_segment_2.csv. The first 168 rows are shown in source order.

What I built

I turned the source workbooks into consistent time-series data, screened sensors for missing readings and documented faults, and prepared continuous segments for analysis. I compared moving-average and Savitzky-Golay filtering, choosing the latter because it retained more of the peaks in our NO₂ comparisons.

One useful lesson: a nearly complete dataset can still be unreliable. The NO₂ S9 sensor had only 0.84% missing readings, but a documented drift issue affected 67.2% of its records. My quality checks explicitly excluded it.

Beyond filtering: the full system

The team compared AM, FM, ASK, FSK and PSK — different ways of carrying information in a signal — to assess how well each recovered data after simulated channel noise. We measured reconstruction error, signal similarity, noise levels and bit errors, depending on the scheme.

  • Transmission and recovery: compare the received information with the original input
  • Digital telemetry: convert readings into binary data using PCM encoding, line coding and integrity checks
  • Monitoring: a six-tab Streamlit dashboard for trends, threshold events, drift, alerts and transmission quality

The saved tests reported no bit errors for ASK, FSK or PSK under those test conditions. The comparison evaluates our simulated implementations, rather than establishing one scheme as universally best.
